# 设备温度告警、采样中断、热暴露、设备组并发告警、告警修订审计、单机告警确认、告警试算、告警修订快照、同组温度偏离诊断、组内温度时差估计、阈值触及预测、告警响应时限与单机告警派生数据对账 API

基于 **Python + FastAPI + SQLite** 的设备监控服务，包含十三个相互独立的能力：

1. **温度告警**：按阈值与连续计数规则判定每台设备的单机告警区间；
2. **采样中断（缺测）**：按每台设备配置的最大采样间隔 `M` 与确认宽限 `G` 判定缺测区间；
3. **热暴露积分（heat exposure）**：复用读数与采样配置 `M`，在查询窗口内对温度做线性插值，统计有效覆盖时长、高于基线 `T` 的时长与超出 `T` 的温度·秒积分；
4. **设备组并发告警**：把若干台设备组成设备组并设定最少同时告警数 `K`，按当前成员的单机告警区间生成「至少 `K` 台同时告警」的组级告警区间；
5. **告警修订审计**：阈值修改与读数写入每次实际改变阈值或温度时，在同一写事务内为设备追加一条连续编号的修订记录（输入变化 + 告警区间差异），可分页查询；
6. **单机告警确认**：对当前仍开启的单机告警按开启时刻写入确认人与确认时间（带修订号乐观并发控制），确认随告警开启时刻在重算中保留或同步删除，持久化可查；
7. **告警试算**：在真正修改阈值或读数之前，提交候选阈值与/或候选读数进行试算（dry run），返回按当前数据重算出的告警区间及相对当前区间的新增/撤销差异，整个请求不落库；
8. **告警修订快照**：按修订号回看单机状态——在同一读快照中取出当前阈值、读数与目标修订之后的全部变更，按修订号倒序在内存中撤回，复原该修订完成时的阈值与读数，并用同一套状态机重算当时的告警区间；查询只读、不落库，也不带入当前告警确认；
9. **同组温度偏离诊断**：在查询窗口内逐个检查目标设备的采样点，与**同组其他成员**同刻取值（原值或按各自 `M` 约束的线性插值）的中位数比较，找出连续偏离点数达到 `min_samples` 的偏离段；即查即算、不落库；
10. **阈值触及预测**：取回看窗口内最新连续采样段（相邻间隔 `≤ M`，最多 30 点），以 `as_of` 为零点对温度做稳健直线拟合（斜率、截距均取中位数），预测未来触及当前阈值 `H` 的时刻；即查即算、不落库；
11. **告警响应时限**：为设备保存正整数响应时限 `D`（秒）；按带时区的 `as_of` 列出当前仍开启、未确认且 `opened_at ≤ as_of` 的告警，扣除缺测时间后统计累计可观测秒数、是否已达到 `D` 与首次达到 `D` 的 UTC 时刻；策略持久化、状态即查即算。
12. **组内温度时差估计**：对组内两台不同成员（目标与参考），在查询窗口内遍历目标的每个采样时刻 `t` 与整数秒偏移 `lag ∈ [-max_lag, max_lag]`，取参考在 `t + lag` 的温度（原值或按参考自身 `M` 约束的线性插值，不外推）配对比较，按「温差绝对值中位数最小 → 配对数最多 → `|lag|` 最小 → `lag` 最小」择优；即查即算、不落库。
13. **单机告警派生数据对账**：告警是「读数 + 阈值」的派生数据。`GET /devices/{device_id}/alarm-consistency` 在**同一 SQLite 读快照**中按当前阈值与全部读数重算告警，与已存告警行按开启、关闭时刻**逐项（多重集）计数比较**，列出缺失、多余与重复的告警区间，并列出开启时刻无对应重算告警的确认（孤儿确认）；`POST /devices/{device_id}/alarm-reconcile` 在 `BEGIN IMMEDIATE` 事务中重新核对，有差异时重建告警并清理孤儿确认（开启时刻仍匹配的首次确认保留），不改读数、阈值与修订历史。

十三者复用同一套设备与读数数据，互不影响。

## 告警规则

每台设备设有触发阈值 `H` 与恢复阈值 `L`（要求 `H > L`）。将设备的全部读数按**采样时间**升序排列后：

- **开启告警**：连续 3 条读数温度 `≥ H`，在第 3 条样本的采样时间开启告警；
- **关闭告警**：告警开启后，连续 2 条读数温度 `≤ L`，在第 2 条样本的采样时间关闭告警；
- 其余读数（开启计数中 `< H`、关闭计数中 `> L`）会中断相应的连续计数，计数清零。

## 采样中断（缺测）规则

每台设备可独立配置：

- **最大采样间隔 `M`**（正整数秒，`M ≥ 1`）：相邻读数允许的最大间隔；
- **确认宽限 `G`**（非负整数秒，`G ≥ 0`）：末条读数超过应到时间后，再等待 `G` 秒才确认「进行中」缺测。

查询缺测区间时（必须带参数 `as_of`，且为**带时区**的时间戳），只使用采样时间 **不晚于 `as_of`** 的读数，全部统一换算为 UTC 后判定：

- **已恢复区间（recovered）**：相邻两条读数的间隔**严格大于** `M` 时，区间为「前一条采样时间 + `M`」→「后一条采样时间」；
- **进行中区间（ongoing）**：末条读数距 `as_of` **严格大于 `M + G`** 时，追加一个「末条采样时间 + `M`」开始、**结束时间为空（`null`）** 的区间；
- **没有读数不推断任何缺测**；相邻间隔**恰为 `M` 不算缺测**；距 `as_of` 恰为 `M + G` 也尚未确认缺测。

缺测区间在查询时按**当前数据与当前 `M`/`G`** 实时计算（不存储）：同一时刻的更正不会新增采样点，晚到读数会自动填补/缩短区间，修改 `M`、`G` 后下次查询立即按新配置更新。

## 热暴露（heat exposure）规则

`GET /devices/{device_id}/heat-exposure` 复用设备的全部读数与采样配置中的最大采样间隔 `M`（未配置 `M` 时返回 **409**）。查询参数：

- **`start` / `end`**（必填）：查询窗口的起止时刻，必须是**带时区**的时间戳，且要求 `start < end`，否则返回 422；
- **`T`**（必填，区分大小写）：有限数值的温度基线；`NaN`、无穷大返回 422。

计算规则（全部时间统一换算为 **UTC**）：

- 对**相邻两条读数**，仅当采样间隔 **不超过 `M`**（间隔恰为 `M` 可以）时，在两者之间按时间对温度做**线性插值**；
- 每条插值线段先**裁剪到查询窗口** `[start, end]`，因此窗口边界可以由窗外相邻读数插值确定；
- 裁剪后的线段若**跨越 `T`**，在交点处拆分：仅温度严格 `> T` 的部分计入 `above_seconds` 与 `excess_degree_seconds`（温度恰为 `T` 不算高于）；
- **长缺测段**（相邻间隔 `> M`）不插值；**首条读数之前、末条读数之后**的时间也**不外推**——这些时间不计入覆盖；
- **极端有限温度不溢出、最小正读数不下溢**：读数与 `T` 均为有限值时，窗口边界的插值温度在线段端点的**标度超出高度**（端点温度 − `T`，除以共同的 2 的幂标度）之间做**仿射插值**求值，并且**从较近的一个端点**取时间比例；交点比例与（温度 − `T`）面积都在三者绝对值最大值导出的**同一 2 的幂标度**上计算——标度取「不超过该最大绝对值的最大 2 的幂」（由 `frexp` 的二进制指数给出，即使输入是最大有限浮点数也不会在取标度时溢出），除以 2 的幂是精确的，标度后各值落在 [−2, 2)；并且标度在面积还原时**最后才乘回**（先乘有界的标度高度与交点比例）。因此：
  - 相邻读数是 `-1e308` → `1e308` 这样的合法极值、且 `T` 接近端点时，交点比例即便小到约 `1e-16` 也不会因 `1 − 比例` 相消而丢成 0，其三角形面积照常保留，且**窗口多长都不会因中间乘积溢出而变成 `inf`**。例如 `M=10` 秒、`0` 秒读数 `-1e308`、`10` 秒读数 `1e308`、窗口恰覆盖这 10 秒且 `T=9.999999999999998e307` 时，返回 `covered_seconds=10`、`excess_degree_seconds≈9.9584463529e276`（有限值）；此时高于 `T` 的时长约 `9.98e-16` 秒，`above_seconds` 按接口六位小数显示为 `0`（面积并未丢）。`M=1` 秒的同样情形面积为其十分之一 `≈9.9584463529e275`；
  - 端点温差达到浮点表示极限的合法极值也不再在取标度时抛出 `OverflowError`：例如整秒读数 `-1` → 最大有限浮点数（`sys.float_info.max`）、`M=1` 秒、`T=0` 时，整段几乎都高于基线，正常返回 `covered_seconds=1`、`above_seconds=1`，面积约为最大有限浮点数的一半（`≈8.9884656743e307` 度·秒）；
  - 端点温差极小的合法下溢情形也不会除零：例如读数 `0` → `5e-324`（最小正次正规数）、`T=0` 时，整段严格高于 `T`，正常返回 `covered_seconds=1`、`above_seconds=1`，而面积约 `2.5e-324` 度·秒，按现有精度显示为 `0`；
  - **裁剪边界保留微秒相对整段跨度的精度**：窗口边界先换算为相对线段起点的**整数微秒偏移**，边界温度从**较近端点**做仿射插值。若改从远端点取比例（或任何 `1 − f` 形式），当边界距末端 1 微秒、整段长达 `1e11` 秒时，比例 `1 − 1e-17` 在 float64 中恰舍入为 `1.0`，边界温度会被吸附到端点值。例如 `M=100000000000` 秒、`2026-01-01T00:00:00Z` 读数为负的最大有限浮点数、`5194-11-16T09:46:40Z` 读数为正的最大有限浮点数、`T` 取最大有限浮点数的前一个可表示数，查询**最后一微秒**（`5194-11-16T09:46:39.999999Z` ~ `5194-11-16T09:46:40Z`）时：边界真实插值温度介于 `T` 与端点之间，整窗严格高于 `T`，返回 `covered_seconds=1e-6`、`above_seconds=1e-6`、`excess_degree_seconds≈1.8160709960e286`（按吸附到端点的旧算法会偏高为 `≈1.9958403095e286`，即整整一个端点 ulp 的高度）。对称地，首微秒窗口在 `T` 取负极值的后一个可表示数时完全低于基线（交点约在首条读数后 5.5 微秒），返回 `above_seconds=0`、面积为 `0`。

  极值示例：`M=1` 秒、`0` 秒读数 `-1e308`、`1` 秒读数 `1e308`、窗口恰覆盖这 1 秒且 `T=0` 时，返回 `covered_seconds=1`、`above_seconds=0.5`、`excess_degree_seconds=2.5e307`（**仅当真实积分本身超出浮点表示范围时**结果才为无穷，例如最大有限浮点数在基线 `T=0` 上持续超过 2 秒）；
- 结果在每次查询时按**当前读数与当前 `M`** 实时计算：晚到读数、读数更正、`M` 变化后，下一次查询立即反映。

返回字段：

- `covered_seconds`：窗口内被有效插值覆盖的秒数；
- `above_seconds`：覆盖时间中温度严格高于 `T` 的秒数；
- `excess_degree_seconds`：窗口内 `max(温度 − T, 0)` 对时间的积分（温度·秒），线性段按（交点拆分后的）梯形面积求和。

## 设备组并发告警规则

设备组把若干台**已存在的设备**组织为一个整体，按「同一时刻处于告警的成员台数」产生组级告警。

**配置（`PUT /groups/{group_id}`）**：新建或整体替换一个组，请求体为非空成员列表与最少同时告警数 `K`：

- 成员列表必须**非空**且**不含重复**，否则返回 422；
- 每个成员都必须是**已存在的设备**（即已设置阈值），否则返回 404；
- `K` 为整数，要求 **`1 ≤ K ≤ 成员数`**，否则返回 422；
- 配置持久化在 SQLite 中，重启不丢失；重复调用即更新，可用 `GET /groups/{group_id}` 查询当前配置（组不存在返回 404）。

**查询（`GET /groups/{group_id}/alarms`）**：按当前成员的**单机告警区间**生成组告警（组不存在返回 404）：

- 单机区间按半开区间 **`[opened_at, closed_at)`** 处理，未关闭（`closed_at` 为空）视为**持续**；
- 同一时刻**至少 `K`** 台成员处于告警时**开启**组告警，并发数**跌破 `K` 台**时**关闭**；
- **同一时刻的开启与关闭先合并（按净额）处理**：例如某台在 `t` 关闭、另一台恰在 `t` 开启，若并发数量并未实际跌破 `K`，组告警**不拆段**，也**不会返回零时长区间**；
- 返回按**开启时间升序**排列的区间；进行中的组告警 **`closed_at` 为 `null`**；所有时间统一为 **UTC**（`Z` 结尾）。
- 组告警**不存储**，每次查询按当前成员、当前 `K` 与成员设备的**当前单机告警**实时计算：调整成员或 `K`、写入晚到读数、更正读数、修改单机阈值后，**下一次查询**立即按新状态重算。

## 同组温度偏离规则

`GET /groups/{group_id}/peer-deviations` 诊断一台设备相对**同组其他成员**的**持续温度偏离**。查询参数：

- **`device_id`**（必填）：目标设备，必须是该组的**成员**（组不存在返回 404；设备不是该组成员返回 404）；
- **`start` / `end`**（必填）：查询窗口的起止时刻，必须是**带时区**的时间戳，且要求 `start < end`，否则返回 422；
- **`delta`**（必填）：**有限正数**的偏离阈值；`NaN`、无穷大、`≤ 0` 均返回 422；
- **`min_samples`**（必填）：构成一段持续偏离所需的最少连续偏离点数，必须是**整数 `≥ 2`**，否则返回 422。

目标设备**未配置采样间隔 `M` 时返回 409**（与热暴露、缺测接口一致）。

计算规则（全部时间统一换算为 **UTC**，逐个处理目标设备在 **`[start, end)`** 内的采样点）：

- 对每个目标采样点，分别求**其他成员**在同一时刻的温度：
  - 该成员在**同一时刻有读数**时取**原值**；
  - 否则在该成员**相邻两条读数**之间按时间做**线性插值**，但仅当这两条读数的间距 **≤ 该成员自己的最大采样间隔 `M`**；间距更大则该成员此刻无值；
  - **首条读数之前、末条读数之后不外推**；**未配置 `M` 的成员不参与**比较；
- 当该时刻**至少两名**其他成员有值时，取这些值的**中位数**（偶数个取中间两值的平均）；目标温度与中位数的**绝对差严格大于 `delta`** 时，该采样点记为一个**偏离点**（恰等于 `delta` 不算偏离）；
- **连续段**在以下任一情况下中断：可比较成员**不足两名**、该点**未偏离**、或**目标相邻采样间距 > 目标设备的 `M`**；
- 一段连续偏离点数**达到 `min_samples`** 时输出一个偏离段：首末偏离点时刻、点数与段内**最大绝对差**；结果按 **UTC 升序**返回。

偏离结果**不存储**：每次查询时在**同一 SQLite 读快照**中取当前成员、当前采样配置与全部读数实时计算——晚到读数、读数更正、成员调整或 `M` 变化后，**下一次查询**立即反映。

## 组内温度时差规则

`GET /groups/{group_id}/lag` 估计组内两台不同成员（目标 `target_id` 与参考 `reference_id`）之间的温度时差。查询参数：

- **`target_id` / `reference_id`**（必填）：目标与参考设备，都必须是该组的**成员**且**互不相同**（组不存在、任一设备不是成员返回 404；两者相同返回 422）；
- **`start` / `end`**（必填）：查询窗口的起止时刻，必须是**带时区**的时间戳，且要求 `start < end`，否则返回 422；只遍历目标在 **`[start, end)`** 内的采样时刻；
- **`max_lag`**（必填）：整数秒偏移上限，要求 **`1 ≤ max_lag ≤ 300`**，否则返回 422；
- **`min_pairs`**（必填）：一个偏移被采纳所需的最少配对数，必须是**整数 `≥ 3`**，否则返回 422。

**参考设备未配置采样间隔 `M` 时返回 409**（目标设备不需要配置 `M`）。

计算规则（全部时间统一换算为 **UTC**）：

- 遍历目标在 `[start, end)` 内的每个 UTC 采样时刻 `t` 与每个整数秒偏移 `lag ∈ [-max_lag, max_lag]`，取参考在 `t + lag` 的温度：
  - 参考在**该时刻有读数**时取**原值**；
  - 否则在参考**相邻两条读数**之间按时间做**线性插值**，但仅当这两条读数的间距 **≤ 参考自己的最大采样间隔 `M`**（间距恰为 `M` 可以）；间距更大则该点此刻无值；
  - **首条读数之前、末条读数之后不外推**，该目标点在此偏移下不计入配对；
- 配对数 **`≥ min_pairs`** 的偏移成为候选，依次按以下规则择优：
  1. **温差绝对值中位数最小**（偶数个取中间两值的平均）；
  2. **配对数最多**；
  3. **`|lag|` 最小**；
  4. **`lag` 最小**；
- 返回最优偏移的 `lag`、配对数 `pairs` 与中位绝对温差 `median_abs_diff`；**没有任何偏移达到 `min_pairs`** 时返回 `status = insufficient_data`、`lag = null`（`pairs = 0`、`median_abs_diff = null`）。

时差结果**不存储**：每次查询时在**同一 SQLite 读快照**中取当前成员、参考的采样配置与两台设备的全部读数实时计算——晚到读数、读数更正、成员调整或 `M` 变化后，**下一次查询**立即反映。

## 阈值触及预测规则

`GET /devices/{device_id}/forecast` 按当前读数趋势预测设备温度**未来触及当前阈值 `H` 的时刻**。查询参数：

- **`as_of`**（必填）：预测零点时刻，必须是**带时区**的时间戳，否则返回 422；
- **`lookback`**（必填）：回看窗口，**正整数秒**，只使用 `[as_of - lookback, as_of]` 内的读数；
- **`horizon`**（必填）：预测时限，**正整数秒**，触及时刻须不超过 `as_of + horizon`。

设备不存在返回 **404**；设备**未配置采样间隔 `M` 返回 409**（与缺测、热暴露、偏离接口一致）。

计算规则（全部时间统一换算为 **UTC**，以 `as_of` 为零点）：

- **取段**：只取 `[as_of - lookback, as_of]` 内**最新连续采样段**——从窗口内最新一条读数向前，相邻间隔 **≤ `M`**（恰为 `M` 可以）才连续，最多取 **30 个点**（保留最新的）；`as_of` 之后的读数不参与；
- **数据不足（insufficient_data）**：末点距 `as_of` **严格大于 `M`**（采样已中断），或段内**不足 3 个点**；
- **拟合**：斜率 `b` 为**所有点对**「温差 ÷ 时差」的**中位数**（Theil–Sen 稳健估计）；截距 `a` 为各点「温度 − `b` × 相对秒数」的**中位数**，即趋势线在 `as_of` 时刻的取值；
- **判定**：当 **`b > 0`、`a < H`** 且 **`(H − a) / b ≤ horizon`** 时返回 `predicted`，预计时刻为 `as_of + (H − a) / b` 秒（UTC）；其余情况（不升、已在阈值上、触及太晚）返回 `no_crossing`；
- **非 `predicted` 时预计时刻为 `null`**。

预测结果**不存储**：每次查询时在**同一 SQLite 读快照**中取当前阈值 `H`、采样配置 `M` 与全部读数实时计算——晚到读数、读数更正、阈值或 `M` 调整后，**下一次查询**立即反映。

## 告警响应时限规则

每台设备可独立保存一个**正整数秒**的告警响应时限 `D`（`D ≥ 1`）。策略持久化在 SQLite 中；每条告警的响应状态在查询时按**当前告警、当前确认、当前读数、当前 `M` 与当前 `D`** 实时计算，不存储。

**保存策略（`PUT /devices/{device_id}/response-policy`）**：

```json
{"deadline": 300}
```

- `deadline` 为**正整数秒**，`0`、负数、小数、非数字均返回 422；
- 设备不存在（未设阈值）返回 **404**；重复调用即为更新（upsert）；
- 可用 `GET /devices/{device_id}/response-policy` 查询当前策略，尚未保存时返回 **409**。

**查询状态（`GET /devices/{device_id}/response-status?as_of=...`）**：

- **`as_of`**（必填）：查询时刻，必须是**带时区**的时间戳（不带时区或缺失返回 422），统一换算为 UTC；
- 只列出当前**仍开启**（`closed_at` 为空）、**未确认**且 **`opened_at ≤ as_of`** 的告警，按开启时间升序；
- 设备不存在返回 **404**；**未配置响应时限 `D` 或未配置采样间隔 `M` 均返回 409**（两者皆缺时在错误信息中一并指出）。

**可观测时间计算**（只使用采样时间 **`≤ as_of`** 的读数，全部换算为 UTC，在 **`[opened_at, as_of]`** 窗口内计量）：

- 相邻两条读数的间隔**严格大于 `M`** 时，扣除半开区间 **`[前一条采样时间 + M, 后一条采样时间)`**（恰为 `M` 不扣除）；
- 末条读数距 `as_of` **严格大于 `M`** 时，扣除 **`[末条采样时间 + M, as_of]`**；
- 所有扣除区间都**裁剪到 `[opened_at, as_of]`**：告警开启之前的缺测不扣除，裁剪后为空的区间忽略；
- 窗口总秒数减去全部扣除秒数，即**累计可观测秒数** `observable_seconds`；
- 累计可观测时间**首次累计到 `D` 秒的 UTC 时刻**为 `deadline_reached_at`；未达到则为 **`null`**，`deadline_reached` 为 `false`。
- **精度一致（微秒边界修正）**：累计、达标判定与首次达标时刻都以**微秒级精确时长**（与存储时间戳同精度的整数运算）计算，不做浮点近似比较。因此当累计可观测时间**恰好等于 `D`** 时（例如 `M=1` 秒、`D=8` 秒，多个缺测段之间的可观测片段为 `2.279285 + 3.227535 + 1.863487 + 0.629693 = 8` 秒），`deadline_reached` 必为 `true`，且 `deadline_reached_at` 必为**真实累计达到 `D` 的 UTC 时刻**——不会出现 `observable_seconds=8.0`、`deadline_reached=true` 而 `deadline_reached_at=null` 的矛盾结果；差 1 微秒未达 `D` 时仍返回 `false` / `null`。

返回示例（读数在 `00:00~00:02` 连续高温使告警于 `00:02` 开启，之后 `00:05`、`00:06` 才有读数；`M=60, D=180`，`as_of=00:10`）：

```json
[
  {
    "device_id": "dev-1",
    "opened_at": "2026-01-01T00:02:00Z",
    "as_of": "2026-01-01T00:10:00Z",
    "deadline": 180,
    "observable_seconds": 180.0,
    "deadline_reached": true,
    "deadline_reached_at": "2026-01-01T00:07:00Z"
  }
]
```

- 上例中 `[00:03, 00:05)`（相邻间隔 3 分钟 > `M`）与 `[00:07, 00:10]`（末点 `00:06` 距 `as_of` 4 分钟 > `M`）各扣除 120、180 秒；480 秒窗口剩余 180 秒，`D=180` 恰在 `00:07` 达到。

响应状态**不存储**：告警及其确认、采样配置 `M`、读数与策略 `D` 在**同一 SQLite 读快照**中读取并实时计算——晚到读数、读数更正、告警重算（开启时刻移动/告警关闭）、告警确认或调整 `M`/`D` 后，**下一次查询**立即反映最新状态。

## 告警修订审计规则

每次 **阈值 PUT** 或 **读数批量 POST** 使设备的阈值或某个采样点的温度**实际发生变化**时，服务在**同一 SQLite 写事务**内为这台设备追加一条修订记录：

- **修订号**：每台设备独立编号，**从 1 起连续递增**（无空洞、不重复）；
- **操作类型**：`thresholds`（阈值变更）或 `readings`（读数批次）；
- **输入变化**：
  - 阈值变更：记录**前后阈值**（`old_h`/`old_l` → `new_h`/`new_l`）；**初创设备的旧阈值为 `null`**；
  - 读数批次：记录**本批每个实际变动的采样点**的温度前后值（新采样点旧值为 `null`）；**批次内同一采样时刻以最后一条为准**，与存储值相同的点不记入；
- **告警区间差异**：重算前后告警区间的对比结果，按**开启、关闭时刻**比较（不依赖告警行 ID）——**移动**的告警记为「撤销旧区间 + 新增新区间」，分别进入 `withdrawn_alarms` 与 `added_alarms`（两者均可为空）。

**同值重试不记修订**：重复设置相同阈值、或批次内所有读数与存储值一致时，不产生新修订。并发写入通过写事务串行化（`BEGIN IMMEDIATE`），保证修订号连续且前后状态一致。修订记录持久化在 SQLite 中，**重启后历史可查**；**旧库**（本功能上线前创建的库）从**首次新写入**起记录，此前的历史不补记。

查询：`GET /devices/{device_id}/alarm-revisions`，按修订号**升序**分页：

- **`after`**（可选，默认 `0`）：**排他游标**，只返回修订号**严格大于** `after` 的记录；翻页时传入上一页最后一条的 `revision`；负数返回 422；
- **`limit`**（可选，默认 `100`）：每页最大条数，必须是**正整数**，否则返回 422。

## 单机告警确认规则

每台设备的告警确认按**告警开启时刻**（`opened_at`）关联：同一台设备、同一开启时刻最多一条确认，记录**确认人**与**确认时间**（服务端 UTC 时间）。

- **确认对象**：只能确认**当前仍开启**的告警。`opened_at` 必须带时区，服务端统一换算为 **UTC 瞬时**匹配；设备不存在、或没有在该时刻开启且仍开启的告警（含已关闭的）返回 **404**；
- **乐观并发控制**：请求携带 `expected_revision`（即 `GET /devices/{device_id}/alarms` 响应头 `X-Alarm-Revision` 返回的修订号）。写入确认时在**同一 SQLite 写事务**（`BEGIN IMMEDIATE`）内核对设备当前最新修订号，**不一致返回 409**——说明告警状态已被并发修改，需重新查询后再确认；
- **幂等**：重复确认同一开启时刻（即使换了确认人）**不改变首次确认的确认人与确认时间**，返回已存在的确认；
- **重算时的保留 / 同步删除**：读数更正、晚到读数或阈值变更触发告警重算时，按开启时刻关联确认——开启时刻不变的告警**保留确认**（即使关闭时间变化，含由开启变为关闭）；开启时刻**移动**或告警被**撤销**时，其确认在**同一事务内同步删除**（之后告警即使回到原开启时刻，确认也不会复活）；
- 确认持久化在 SQLite 中，**重启后可查**；确认本身**不产生新的告警修订号**。

## 告警试算规则

`POST /devices/{device_id}/alarm-preview` 用于在**真正修改阈值或读数之前**试算一台设备的告警结果，**整个请求不落库**（读数、阈值、告警、确认与修订历史都不会改变）。

**请求体**（`thresholds` 与 `readings` **至少提供一项**，否则返回 422）：

- **`thresholds`**（可选）：候选阈值 `{"h": ..., "l": ...}`，要求 `H > L` 且均为**有限数**，否则返回 422；省略时使用设备**当前阈值**；
- **`readings`**（可选）：候选读数列表，`sampled_at` 必须**带时区**、`temperature` 必须为**有限数**，否则返回 422；省略时只重放当前读数。

**计算方式**：在**同一 SQLite 读快照**中取得设备的当前阈值、全部读数、当前告警与当前修订号，然后在**内存中**叠加候选值后按现有告警规则重算：

- 候选读数按 **UTC 采样瞬时**覆盖现存读数（与偏移写法无关）；**批内同一瞬时以最后一条为准**；
- 候选阈值（若提供）整体替换当前阈值参与重算。

**返回**：`base_revision`（基线修订号，即设备当前告警修订号）、`alarms`（试算得到的告警区间，按开启时间升序），以及相对**当前区间**的差异 `added_alarms` / `withdrawn_alarms`——按**开启、关闭时刻**比较，**区间移动算撤销加新增**（与告警修订审计中的区间差异口径一致）。设备不存在返回 **404**，参数无效返回 **422**。

## 告警修订快照规则

`GET /devices/{device_id}/alarm-revisions/{revision}/snapshot` 回看**指定修订完成时**的单机状态（当时的阈值、读数与告警区间），**整个请求不落库**。

- **`revision`**（路径参数）：目标修订号，必须是**正整数**（否则返回 422）且**不超过设备当前修订号**——超过即修订不存在，返回 **404**；设备不存在同样返回 **404**；
- **复原方式**：在**同一 SQLite 读快照**中取得设备的当前阈值、全部当前读数以及**目标修订之后**（修订号严格大于目标）的全部修订变更，然后在内存中**按修订号倒序**逐个撤回：
  - **读数变更**：变动点的旧值为 `null` 时**删除该采样点**（该点由该修订引入），否则**恢复旧温度**；
  - **阈值变更**：恢复该修订记录的**旧 `H`、`L`**；
- **告警重算**：复原后的读数按 **UTC 采样瞬时**排序，用与线上一致的告警状态机重算告警区间（连续 3 条 `≥ H` 开启、连续 2 条 `≤ L` 关闭）；
- **返回**：目标修订号、当时的 `H`/`L`、当时的读数（按采样时刻升序）与重算出的告警区间；**不携带当前告警确认**——历史快照不含确认信息；
- **只读**：整个请求只有 SELECT，读事务最终回滚，读数、阈值、告警、确认与修订历史均不受影响，可放心反复查询。

## 单机告警派生数据对账规则

告警是「读数 + 阈值」的**派生数据**：正常写入路径每次都会重算并整体替换告警行，因此已存告警本应与状态机的重算结果完全一致。对账接口用于发现并修复因外部改库、历史缺陷等造成的不一致，设备不存在均返回 **404**。

**只读核对（`GET /devices/{device_id}/alarm-consistency`）**：

- 在**同一 SQLite 读快照**中读取设备当前阈值、全部读数、全部已存告警行与全部确认，按当前阈值与读数用同一套状态机（连续 3 条 `≥ H` 开启、连续 2 条 `≤ L` 关闭）重算告警；
- 已存告警与重算告警按 **`(opened_at, closed_at)` 逐项（多重集）计数比较**（不依赖告警行 ID），按开启时刻升序列出：
  - `missing_alarms`：重算有、已存没有的告警区间（含数量，移动的告警记为一条缺失 + 一条多余）；
  - `extra_alarms`：已存数量超出重算数量的告警区间（逐项列出，重复几份列几条）；
  - `duplicate_alarms`：同一区间被存储多份时，**除第一份外的每份重复副本**（与多余区间分开报出）；
- `orphan_acknowledgements`：已存确认中，其 `opened_at` 在重算告警的开启时刻集合里**无对应项**的确认（返回开启时刻、确认人与确认时间）；仅关闭时刻变化不视为孤儿；
- 同时返回 `stored_alarm_count` / `recomputed_alarm_count`（重复行计入）与 `consistent`（缺失、多余、重复、孤儿确认任一非空即为 `false`）；
- **只读不落库**，可反复查询。

**修复（`POST /devices/{device_id}/alarm-reconcile`）**：

- 在一个 **`BEGIN IMMEDIATE` 写事务**内重新核对，返回修复前 `before` 与修复后 `after` 两份与 GET 同口径的对账结果，以及 `fixed`（是否实际改动）；
- 当告警区间存在缺失 / 多余 / 重复差异时，**按当前阈值与全部读数整体重建**该设备的告警行；
- 重建后（或告警行本就一致、仅有孤儿确认时）在**同一事务**内删除开启时刻无对应重算告警的确认；开启时刻仍匹配的告警**保留首次确认**（确认人与确认时间不变，即使关闭时刻变化）——确认表每个开启时刻最多一条；重算已无任何告警时清空该设备的全部确认；
- **不修改读数、阈值与告警修订历史**，对账本身也**不产生新的修订号**；
- **无任何差异时不改动任何告警行与确认**（`fixed=false`，`before` 与 `after` 相同，告警行 ID 保持不变）。

## API 接口

### 1. 设置 / 修改阈值

```
PUT /devices/{device_id}/thresholds
Content-Type: application/json

{"h": 30.0, "l": 20.0}
```

- 首次调用即创建设备；`h` 必须严格大于 `l`，否则返回 422。
- 修改阈值后会按当前全部读数**重算告警**：不再成立的告警被撤销，时间受影响的告警被移动。
- 阈值**实际变化**（含首次创建设备）时，在同一事务内追加一条**告警修订**（见接口 10）；重复设置相同值不记修订。

### 2. 写入读数（支持批量）

```
POST /devices/{device_id}/readings
Content-Type: application/json

{
  "readings": [
    {"sampled_at": "2026-01-01T00:00:00+00:00", "temperature": 31.2},
    {"sampled_at": "2026-01-01T00:01:00+08:00", "temperature": 31.5}
  ]
}
```

- `sampled_at` 必须带时区偏移（如 `+08:00`、`Z`），否则返回 422；服务端统一归一化为 UTC 存储与排序。
- **更正**：同一设备、同一采样时刻（同一瞬时，与偏移写法无关）的再次写入会覆盖旧值。
- **晚到读数**：乱序到达的读数按采样时间插入正确位置。
- 每次写入后按当前全部读数重算告警。设备不存在（未设阈值）时返回 404。
- 批次内**同一采样时刻以最后一条为准**；只要有一个采样点的温度**实际变化**，就在同一事务内追加一条**告警修订**（见接口 10），记录各变动点的温度前后值；全部与存储值相同（同值重试）不记修订。

### 3. 查询告警

```
GET /devices/{device_id}/alarms?status=open&from=2026-01-01T00:00:00Z&to=2026-02-01T00:00:00Z
```

- `status`（可选）：`open`（进行中）/ `closed`（已关闭），缺省返回全部；
- `from` / `to`（可选）：按告警开启时间过滤，需带时区；
- 每个列表项额外携带确认信息：`acknowledged_by`（确认人）与 `acknowledged_at`（确认时间，UTC），未确认为 `null`；
- 响应头 **`X-Alarm-Revision`** 返回设备当前告警修订号（无修订记录时为 `0`），供确认接口的 `expected_revision` 使用；告警列表、确认信息与修订号来自**同一读快照**（同一读事务）；
- 返回示例：

```json
[
  {
    "id": 1,
    "device_id": "dev-1",
    "opened_at": "2026-01-01T00:02:00Z",
    "closed_at": "2026-01-01T00:04:00Z",
    "status": "closed",
    "acknowledged_by": "alice",
    "acknowledged_at": "2026-09-24T01:02:03.456789Z"
  }
]
```

### 4. 配置采样间隔与宽限


### 5. 查询缺测区间

- 设备不存在返回 404；设备存在但未配置 `M`/`G` 返回 409。
- 只计入采样时间不晚于 `as_of` 的读数，输出时间统一为 UTC（`Z` 结尾）。
- 返回示例（`M=60, G=30`，读数在 `00:00` 与 `00:03`，`as_of=00:05`）：

```json
[
  {
    "started_at": "2026-01-01T00:01:00Z",
    "ended_at": "2026-01-01T00:03:00Z",
    "status": "recovered"
  },

    "ended_at": null,
    "status": "ongoing"
  }
]
```

- `recovered`：相邻读数间隔 > `M`，区间从前一条 `+M` 到后一条采样时间；
- `ongoing`：末条读数距 `as_of` > `M + G`，区间从末条 `+M` 开始、`ended_at` 为 `null`。

### 11. 确认单机告警

```
POST /devices/{device_id}/alarm-acknowledgements
Content-Type: application/json

{
  "opened_at": "2026-01-01T08:02:00+08:00",
  "operator": "alice",
  "expected_revision": 2
}
```

- `opened_at`（必填）：要确认的告警的**开启时刻**，必须**带时区**（如 `+08:00`、`Z`），服务端按 **UTC 瞬时**匹配**当前仍开启**的告警；
- `operator`（必填）：确认人，**非空**（纯空白也算空），否则返回 422；
- `expected_revision`（必填，≥ 0）：调用方此前在响应头 `X-Alarm-Revision` 看到的修订号；与设备当前最新修订号**不一致返回 409**（核对与写入在同一 SQLite 写事务内完成）；
- 设备不存在返回 **404**；没有在该时刻开启且仍开启的告警（含已关闭的告警）返回 **404**；
- **首次确认返回 201**；**重复确认返回 200** 与首次的确认人、确认时间（幂等，不覆盖）；确认本身不产生新的告警修订号；
- 返回示例：

```json
{
  "device_id": "dev-1",
  "opened_at": "2026-01-01T00:02:00Z",
  "operator": "alice",
  "acknowledged_at": "2026-09-24T01:02:03.456789Z"
}
```

- 确认结果通过 `GET /devices/{device_id}/alarms` 列表项的 `acknowledged_by` / `acknowledged_at` 查询（见接口 3）。

### 12. 试算单机告警（不落库）

服务地址与端口见「启动」一节（默认 `http://localhost:8000`），试算接口的完整地址为 `POST http://localhost:8000/devices/{device_id}/alarm-preview`：

```
POST /devices/{device_id}/alarm-preview
Content-Type: application/json

{
  "thresholds": {"h": 35.0, "l": 20.0},
  "readings": [
    {"sampled_at": "2026-01-01T00:03:00Z", "temperature": 19.0},
    {"sampled_at": "2026-01-01T08:04:00+08:00", "temperature": 19.0}
  ]
}
```

- `thresholds`（可选）：候选阈值，要求 `h > l` 且均为有限数；省略时使用设备当前阈值；
- `readings`（可选）：候选读数，`sampled_at` 必须带时区、温度必须为有限数；按 **UTC 采样瞬时**覆盖现存读数，批内同一瞬时以最后一条为准；
- 两者**至少提供一项**，否则返回 422；设备不存在返回 404；
- 在**同一读快照**取得当前阈值、读数、告警与修订号后在内存中重算，**不落库**：读数、阈值、告警、确认与修订历史均不受影响，可放心反复试算；
- 返回示例（当前告警为 `00:02` 开启、进行中；候选阈值 `H=35` 使其被撤销）：

```json
{
  "device_id": "dev-1",
  "base_revision": 2,
  "alarms": [],
  "added_alarms": [],
  "withdrawn_alarms": [
    {"opened_at": "2026-01-01T00:02:00Z", "closed_at": null}
  ]
}
```

- 字段说明：`base_revision` 为设备当前告警修订号（试算的基线）；`alarms` 为候选输入下重算出的告警区间；`added_alarms` / `withdrawn_alarms` 为相对当前区间的差异，按开启、关闭时刻比较，**区间移动 = 撤销 + 新增**。

### 13. 查询告警修订快照（单机历史状态，不落库）

服务地址与端口见「启动」一节（默认 `http://localhost:8000`），快照接口的完整地址为 `GET http://localhost:8000/devices/{device_id}/alarm-revisions/{revision}/snapshot`：

```
GET /devices/{device_id}/alarm-revisions/{revision}/snapshot
```

- `revision`（路径参数）：目标修订号，**正整数**（否则返回 422）且**不超过设备当前修订号**（超过即修订不存在，返回 404）；设备不存在返回 **404**；
- 在**同一 SQLite 读快照**中取得当前阈值、全部当前读数与目标修订之后的全部修订变更，在内存中**按修订号倒序**撤回（读数旧值为 `null` 时删除该采样点，否则恢复旧温度；阈值恢复旧 `H`/`L`），复原读数按 **UTC 采样瞬时**排序后用现有状态机重算告警；
- **不落库**，也**不带入当前告警确认**；
- 返回示例（设备当前修订为 3，查询修订 2 完成时的状态）：

```json
{
  "device_id": "dev-1",
  "revision": 2,
  "threshold_h": 30.0,
  "threshold_l": 20.0,
  "readings": [
    {"sampled_at": "2026-01-01T00:00:00Z", "temperature": 31.0},
    {"sampled_at": "2026-01-01T00:01:00Z", "temperature": 31.0},
    {"sampled_at": "2026-01-01T00:02:00Z", "temperature": 31.0}
  ],
  "alarms": [
    {"opened_at": "2026-01-01T00:02:00Z", "closed_at": null}
  ]
}
```

- 字段说明：`revision` 为目标修订号；`threshold_h` / `threshold_l` 为该修订完成时生效的阈值；`readings` 为当时的读数（按 UTC 采样时刻升序）；`alarms` 为按当时阈值与读数重算的告警区间（`closed_at` 为 `null` 表示当时仍开启）。

### 14. 查询同组温度偏离

服务地址与端口见「启动」一节（默认 `http://localhost:8000`），完整地址为 `GET http://localhost:8000/groups/{group_id}/peer-deviations`：

```
GET /groups/{group_id}/peer-deviations?device_id=dev-1&start=2026-01-01T00:00:00Z&end=2026-01-01T01:00:00Z&delta=2.0&min_samples=3
```

- `device_id`（**必填**）：目标设备，必须是该组成员；组不存在或设备不是成员返回 **404**；
- `start` / `end`（**必填**）：带时区的窗口起止时刻，要求 `start < end`；只处理目标在 `[start, end)` 内的采样点；URL 中偏移里的 `+` 需编码为 `%2B`；
- `delta`（**必填**）：有限正数偏离阈值；`min_samples`（**必填**）：整数 `≥ 2`；非法均返回 422；
- 目标设备未配置采样间隔 `M` 返回 **409**；未配置 `M` 的其他成员不参与比较；
- 每个目标采样点与同组其他成员同刻温度（原值或按各自 `M` 约束的线性插值，不外推）的**中位数**比较，绝对差 `> delta` 记为偏离点；可比较成员不足两名、未偏离或目标相邻采样间距 `>` 目标 `M` 都会中断连续段；连续偏离点数达到 `min_samples` 的段按 **UTC 升序**返回；
- 返回示例（目标在 `00:03`~`00:05` 连续 3 点偏离同组中位数超过 `delta`，最大绝对差 3.5）：

```json
[
  {
    "started_at": "2026-01-01T00:03:00Z",
    "ended_at": "2026-01-01T00:05:00Z",
    "samples": 3,
    "max_abs_deviation": 3.5
  }
]
```

- 字段说明：`started_at` / `ended_at` 为偏离段首、末偏离点的 UTC 时刻；`samples` 为段内连续偏离点数；`max_abs_deviation` 为段内最大的「目标温度 − 同组中位数」绝对差。

### 15. 查询阈值触及预测（不落库）

服务地址与端口见「启动」一节（默认 `http://localhost:8000`），完整地址为 `GET http://localhost:8000/devices/{device_id}/forecast`：

```
GET /devices/{device_id}/forecast?as_of=2026-01-01T00:10:00Z&lookback=600&horizon=400
```

- `as_of`（**必填**）：预测零点时刻，必须**带时区**（URL 中偏移里的 `+` 需编码为 `%2B`）；`lookback` / `horizon`（**必填**）：回看窗口与预测时限，均为**正整数秒**；缺失或非法返回 422；
- 设备不存在返回 **404**；未配置采样间隔 `M` 返回 **409**；
- 只取 `[as_of - lookback, as_of]` 内**最新连续采样段**（相邻间隔 `≤ M`，最多 30 点）；末点距 `as_of` > `M` 或不足 3 点时返回 `insufficient_data`；否则以 `as_of` 为零点拟合直线（斜率 `b` 为所有点对温差÷时差的中位数，截距 `a` 为各点温度 − `b`×相对秒数的中位数），`b > 0`、`a < H` 且 `(H − a) / b ≤ horizon` 时返回 `predicted` 与 UTC 预计时刻，其余返回 `no_crossing`；非 `predicted` 时 `predicted_at` 为 `null`；
- 返回示例（`H=30`，00:08~00:10 三条读数 `22/23/24℃，斜率 1/60 ℃/s，预计 360 秒后触及）：

```json
{
  "device_id": "dev-1",
  "as_of": "2026-01-01T00:10:00Z",
  "lookback": 600,
  "horizon": 400,
  "threshold_h": 30.0,
  "samples": 3,
  "slope": 0.016666666666666666,
  "intercept": 24.0,
  "status": "predicted",
  "predicted_at": "2026-01-01T00:16:00Z"
}
```

- 字段说明：`samples` 为参与拟合的最新连续段点数（`insufficient_data` 时为取到的段内点数）；`slope` / `intercept` 为拟合斜率（温度/秒）与 `as_of` 时刻的趋势温度（`insufficient_data` 时为 `null`）；`status` 为 `predicted` / `no_crossing` / `insufficient_data`；`predicted_at` 为预计触及 `H` 的 UTC 时刻（非 `predicted` 时为 `null`）。

- `as_of`（**必填**）：查询时刻，必须**带时区**（URL 中偏移里的 `+` 需编码为 `%2B`）；不带时区或缺失返回 422；
- 列出当前**仍开启、未确认且 `opened_at ≤ as_of`** 的告警（按开启时间升序）；已关闭、已确认或在 `as_of` 之后才开启的告警不返回；
- 设备不存在返回 **404**；未配置 `D` 或未配置采样间隔 `M` 返回 **409**；
- 计时只用采样时间 `≤ as_of` 的读数：相邻间隔 `> M` 扣除 `[前点 + M, 后点)`，末点距 `as_of > M` 扣除 `[末点 + M, as_of]`，均裁剪到 `[opened_at, as_of]`；
- 返回示例（读数 `00:00~00:02` 与 `00:05`、`00:06`，`M=60, D=180`，`as_of=00:10`）：

```json
[
  {
    "device_id": "dev-1",
    "opened_at": "2026-01-01T00:02:00Z",
    "as_of": "2026-01-01T00:10:00Z",
    "deadline": 180,
    "observable_seconds": 180.0,
    "deadline_reached": true,
    "deadline_reached_at": "2026-01-01T00:07:00Z"
  }
]
```

- 字段说明：`observable_seconds` 为窗口内扣除缺测后的累计可观测秒数；`deadline_reached` 表示截至 `as_of` 是否累计达到 `D`；`deadline_reached_at` 为首次达到 `D` 的 UTC 时刻，未达到为 `null`；`as_of` 为归一化到 UTC 的查询时刻；`deadline` 回显当前策略。
- **精度一致（微秒边界修正）**：累计、达标判定与首次达标时刻使用同一**微秒级精确时长**计算（整数运算，非浮点近似），三者不会相互矛盾：累计恰好等于 `D` 时 `deadline_reached=true` 且 `deadline_reached_at` 为真实累计达到 `D` 的 UTC 时刻（不为 `null`）；未达 `D` 时仍为 `false` / `null`。
- 状态**不存储**：告警、确认、`M`、读数与 `D` 来自**同一 SQLite 读快照**；晚到、更正、重算、确认或配置调整后下次查询即反映。

### 17. 查询组内温度时差（不落库）

服务地址与端口见「启动」一节（默认 `http://localhost:8000`），完整地址为 `GET http://localhost:8000/groups/{group_id}/lag`：

```
GET /groups/{group_id}/lag?target_id=dev-1&reference_id=dev-2&start=2026-01-01T00:00:00Z&end=2026-01-01T01:00:00Z&max_lag=120&min_pairs=3
```

- `target_id` / `reference_id`（**必填**）：目标与参考设备，均为该组成员且互不相同；组不存在或任一设备不是成员返回 **404**，两者相同返回 **422**；
- `start` / `end`（**必填**）：带时区的窗口起止时刻，要求 `start < end`；只遍历目标在 `[start, end)` 内的采样时刻；URL 中偏移里的 `+` 需编码为 `%2B`；
- `max_lag`（**必填**）：整数秒偏移上限，`1 ≤ max_lag ≤ 300`；`min_pairs`（**必填**）：整数 `≥ 3`；非法均返回 422；
- 参考设备未配置采样间隔 `M` 返回 **409**（目标设备不需要配置 `M`）；
- 对每个目标采样时刻 `t` 与每个整数秒偏移 `lag ∈ [-max_lag, max_lag]`，取参考在 `t + lag` 的温度（同刻有读数取原值，否则仅当相邻读数间距 `≤` 参考的 `M` 时线性插值，**不外推**）；配对数 `≥ min_pairs` 的偏移按「温差绝对值中位数最小 → 配对数最多 → `|lag|` 最小 → `lag` 最小」择优；
- 返回示例（参考比目标慢 45 秒，5 对配对，中位绝对温差 0）：

```json
{
  "group_id": "line-1",
  "target_id": "dev-1",
  "reference_id": "dev-2",
  "start": "2026-01-01T00:00:00Z",
  "end": "2026-01-01T01:00:00Z",
  "max_lag": 120,
  "min_pairs": 3,
  "status": "ok",
  "lag": 45,
  "pairs": 5,
  "median_abs_diff": 0.0
}
```

- 字段说明：`status` 为 `ok` / `insufficient_data`；`lag` 为最优整数秒偏移（`insufficient_data` 时为 `null`）；`pairs` 为最优偏移下的配对数；`median_abs_diff` 为最优偏移下「目标温度 − 参考 `t + lag` 温度」绝对差的中位数（`insufficient_data` 时为 `null`）；
- 结果**不存储**：成员、参考的采样配置与两台设备的读数来自**同一 SQLite 读快照**；晚到读数、更正、成员或 `M` 调整后下次查询即反映。

## 设计说明

- **告警重算**：告警是「读数 + 阈值」的纯函数。写入读数（含更正、晚到）或修改阈值后，对该设备的全部读数重新运行状态机，整体替换其告警记录——因此被撤销的告警自动消失、受影响的告警自动移动到新时间，无需增量维护。
- **缺测即查即算**：缺测区间是「读数 + `M`/`G` + `as_of`」的纯函数，不持久化、每次查询实时计算。先按 `as_of` 过滤读数（UTC 比较），再扫描相邻读数与末条读数，因此更正、晚到读数与配置变更都天然反映在下一次查询中；同瞬时读数因 `(device_id, sampled_at)` 主键而不会产生第二个采样点。
- **热暴露即查即算**：热暴露是「读数 + `M` + 窗口 + `T`」的纯函数，同样不持久化。扫描相邻读数时跳过间隔 `> M` 的缺测段，对每条有效线段裁剪到查询窗口后，用端点温度的线性表达式求覆盖时长；跨越 `T` 时按比例定位交点并拆分，高于部分的时长直接取段长、温度·秒积分取（拆分后的）梯形面积，因此结果在亚秒级也是精确的。窗口边界只在相邻两读数之间插值，长缺测段与首末读数之外一律不外推。**数值上按极端有限温度设计**：窗口边界的插值温度取端点的凸组合（权重 ∈ [0,1]），交点比例与温度差都在减半后的值上计算（`0.5·a − 0.5·b` 不会上溢），因此相邻读数为 `-1e308` → `1e308` 这类合法极值时仍返回有限的覆盖时长、高于时长与温度·秒积分，不再因斜率 `（v1 − v0）` 上溢而产生 `NaN`。
- **设备组并发告警即查即算**：组只持久化成员列表与 `K`（`device_groups` 与 `group_members` 两表，成员带提交序号以便原样返回），组告警本身不存储。查询时取**当前成员**设备的**当前告警**区间，把每条区间的开启记 `+1`、关闭记 `−1`，**同一时刻的事件先按净额合并**，再按时间升序扫描：并发数由 `< K` 升至 `≥ K` 时开启组告警，由 `≥ K` 跌至 `< K` 时关闭。因此同一时刻「一台关闭、另一台开启」不会误拆段，只要数量没有真正跌破 `K` 区间就连续，也不会产生零时长区间；成员调整、`K` 调整、晚到读数、读数更正、单机阈值修改都天然反映在下一次查询中。未关闭的单机告警没有关闭事件，自然视为持续，进行中的组告警 `closed_at` 为 `null`。
- **告警修订审计随写记录**：阈值 PUT 与读数批量 POST 在提交前以 `BEGIN IMMEDIATE` 开启写事务，把并发写入串行化；在**同一事务**内先比对出实际变化（阈值前后值、批次内「同一时刻以最后一条为准」去重后的温度前后值），重算告警，再追加修订记录（`alarm_revisions` + 读数变化表 `alarm_revision_readings` + 区间差异表 `alarm_revision_alarms`）。修订号取该设备当前最大值 + 1，因事务串行而连续无空洞；阈值或温度没有实际变化（同值重试）时不写修订。区间差异按 `(opened_at, closed_at)` 集合比较，与告警行 ID 无关，因此移动的告警自然呈现为「撤销旧区间 + 新增新区间」。修订记录持久化，重启后可查；旧库通过 `CREATE TABLE IF NOT EXISTS` 自动补表，从首次新写入起记录。
- **单机告警确认按开启时刻关联**：确认存于 `alarm_acknowledgements` 表，主键 `(device_id, opened_at)`。确认接口在 `BEGIN IMMEDIATE` 写事务内先核对设备当前最新修订号（与 `expected_revision` 不一致返回 409），再按 UTC 开启时刻匹配仍开启的告警（无则 404），最后 `INSERT OR IGNORE` 写入——重复确认自然幂等，首次确认人与时间不变。每次告警重算（读数更正/晚到、阈值变更）在**同一事务**内删除开启时刻已不存在的确认：开启时刻不变（哪怕关闭时间变化、由开启变关闭）确认保留；开启时刻移动或告警撤销则确认同步删除。查询告警时用 `LEFT JOIN` 在**同一读事务快照**中取回每条告警的确认信息与当前修订号（`X-Alarm-Revision` 响应头）。确认持久化，重启可查；确认本身不产生新的告警修订号。
- **告警试算即查即算、不落库**：告警是「读数 + 阈值」的纯函数，因此试算无需写入任何数据即可得出结果。试算接口在**同一读事务快照**中取回当前阈值、全部读数、当前告警区间与当前修订号（`base_revision`），随后在内存中把候选读数按 UTC 采样瞬时叠加到现存读数上（同一瞬时候选覆盖现存、批内最后一条为准），候选阈值（若提供）替换当前阈值，用同一套状态机重算告警区间；与当前区间按 `(opened_at, closed_at)` 集合比较得出新增/撤销差异（移动 = 撤销 + 新增），与修订审计的口径一致。整个请求只有 SELECT，读事务最终回滚，读数、阈值、告警、确认与修订历史都不会改变，可反复试算。
- **告警修订快照即查即算、不落库**：修订审计记录了每次变更的完整前后状态（阈值前后值、每个变动采样点的温度前后值），因此任意修订完成时的单机状态都可以从当前状态回滚复原。快照接口在**同一读事务快照**中取回当前阈值、全部当前读数与目标修订之后的全部修订变更，随后在内存中**按修订号倒序**逐个撤回：读数变更的旧值为 `null` 时删除该采样点（该点由该修订引入）、否则恢复旧温度，阈值变更恢复旧 `H`/`L`；撤回完成后读数按 UTC 采样瞬时排序，用与线上一致的告警状态机重算出当时的告警区间。目标修订号必须是正整数（否则 422）且不超过当前修订号（否则 404）。整个请求只有 SELECT，读事务最终回滚，不改库；响应只含当时的阈值、读数与告警区间，**不带入当前告警确认**。
- **同组温度偏离即查即算、不落库**：偏离段是「当前成员 + 各成员采样配置 `M` + 全部读数 + 查询参数」的纯函数，不持久化。查询时在**同一 SQLite 读快照**中取回组的当前成员、成员的采样配置与全部读数，随后按 UTC 升序逐个处理目标在 `[start, end)` 内的采样点：其他成员同刻有读数取原值，否则仅当其相邻读数间距 `≤` 自己的 `M` 时线性插值（首末读数之外不外推，未配置 `M` 的成员不参与）；至少两名成员有值时取中位数，绝对差严格大于 `delta` 记为偏离点。可比较成员不足、未偏离或目标相邻采样间距 `>` 目标 `M` 都会中断连续段；连续偏离点数达到 `min_samples` 的段输出首末时刻、点数与最大绝对差。目标未配置 `M` 返回 409。晚到读数、更正、成员或 `M` 调整都天然反映在下一次查询中。
- **组内温度时差即查即算、不落库**：时差是「当前成员 + 参考采样配置 `M` + 两台设备读数 + 查询参数」的纯函数，不持久化。查询时在**同一 SQLite 读快照**中取回组的当前成员、参考的采样配置与目标、参考的全部读数，随后遍历目标在 `[start, end)` 内的每个采样时刻 `t` 与每个整数秒偏移 `lag ∈ [-max_lag, max_lag]`：参考在 `t + lag` 同刻有读数取原值，否则仅当其相邻读数间距 `≤` 参考自己的 `M` 时线性插值（首末读数之外不外推，该点在此偏移下跳过）。配对数达到 `min_pairs` 的偏移以 `(中位绝对温差, -配对数, |lag|, lag)` 的字典序取最小——即温差绝对值中位数最小、配对数最多、`|lag|` 最小、`lag` 最小；没有偏移达到 `min_pairs` 时返回 `insufficient_data` 与 `null` 时差。参考未配置 `M` 返回 409，目标与参考须是不同成员。晚到读数、更正、成员或 `M` 调整都天然反映在下一次查询中。
- **阈值触及预测即查即算、不落库**：预测是「当前阈值 `H` + 采样配置 `M` + 全部读数 + 查询参数」的纯函数，不持久化。查询时在**同一 SQLite 读快照**中取回 `H`、`M` 与全部读数，先筛出 `[as_of − lookback, as_of]` 内的采样点，再从最新一条向前取相邻间隔 `≤ M` 的连续段（最多 30 点）；末点距 `as_of` 超过 `M` 或段内不足 3 点时返回 `insufficient_data`。拟合以 `as_of` 为零点：斜率 `b` 取**所有点对**「温差 ÷ 时差」的中位数（Theil–Sen 稳健估计，对个别异常点不敏感），截距 `a` 取各点「温度 − `b` × 相对秒数」的中位数；仅当 `b > 0`、`a < H` 且 `(H − a) / b ≤ horizon` 时返回 `predicted` 与 UTC 预计时刻，否则返回 `no_crossing`，非 `predicted` 时预计时刻为 `null`。晚到读数、更正、阈值或 `M` 调整都天然反映在下一次查询中。
- **告警响应时限策略持久化、状态即查即算**：响应时限 `D` 单独存于 `response_policies` 表（与阈值、采样配置解耦），upsert 持久化、重启可查；每条告警的响应状态**不存储**。查询时在**同一 SQLite 读事务快照**中取回仍开启的告警（`LEFT JOIN` 确认表排除已确认项，并按 `opened_at ≤ as_of` 过滤）、采样配置 `M`、采样时间不晚于 `as_of` 的读数与策略 `D`，缺 `D` 或缺 `M` 均返回 409。计时在 `[opened_at, as_of]` 窗口内进行：相邻读数间隔严格大于 `M` 时构造半开扣除段 `[前点 + M, 后点)`，末点距 `as_of` 严格大于 `M` 时追加 `[末点 + M, as_of]`，每段都先裁剪到窗口（开启之前的缺测不影响该告警，退化段直接跳过）；再按时间升序在相邻扣除段之间累加可观测秒数，累加过程中首次达到 `D` 的时刻即 `deadline_reached_at`（未达到为 `null`）。**累计、达标判定与首次达标时刻统一用微秒级精确时长（`timedelta` 整数运算）计算**，只有返回的 `observable_seconds` 才转为浮点秒数——因此累计恰好等于 `D` 时三者必然一致（`deadline_reached=true` 且 `deadline_reached_at` 为真实达标时刻，不会为 `null`），不受浮点舍入影响。由于所有输入都取自当前快照且不回写，晚到读数、读数更正、告警重算（开启时刻移动/告警关闭）、确认写入以及 `M`/`D` 调整都天然反映在下一次查询中。
- **单机告警派生数据对账即查即算、修复走写事务**：告警是「读数 + 阈值」的纯函数，对账不持久化任何新数据。GET 在**同一读事务快照**中取回阈值、全部读数、已存告警行与确认，用同一套状态机重算，再以 `Counter` 多重集按 `(opened_at, closed_at)` 与已存行**逐项计数比较**：重算多出的副本为 `missing`、已存多出的副本为 `extra`，其中同一区间除第一份外的每份副本另列为 `duplicate`——因此重复存储的告警不会被集合比较掩盖；开启时刻不在重算开启时刻集合中的确认列为孤儿确认。整个请求只有 SELECT，读事务最终回滚。POST 在 `BEGIN IMMEDIATE` 写事务内先取修复前对账结果：`consistent` 时直接提交（不删不插，告警行 ID 与确认原样保留）；否则仅当告警区间有差异时才 `DELETE` + 重插该设备的告警行（无差异时不重建），随后统一删除开启时刻已不重算存在的确认（区间一致但有孤儿确认时也会清理，且不重建告警行），开启时刻仍匹配的首次确认原样保留。修复后在**同一事务快照**内重算 `after` 报告；读数、阈值与 `alarm_revisions*` 表完全不参与写操作，因此修订历史不变、对账本身也不追加修订号。设备不存在（未设阈值）在事务内返回 404，事务随之回滚。
- **时区处理**：所有采样时间归一化为 UTC，以固定宽度（微秒）ISO-8601 字符串存储，字典序即时间序，排序与范围过滤都直接在 SQL 中完成。
- **持久化**：设备配置（阈值、采样配置与告警响应时限 `D`）、读数、告警、告警确认、设备组配置（成员 + `K`）与告警修订记录（`alarm_revisions` / `alarm_revision_readings` / `alarm_revision_alarms`）均存于 SQLite（WAL 模式）；读数以 `(device_id, sampled_at)` 为主键，用 `INSERT ... ON CONFLICT DO UPDATE` 实现更正语义。采样配置存于独立的 `sampling_configs` 表、响应时限存于独立的 `response_policies` 表，与阈值解耦，可分别设置；组配置存于 `device_groups` / `group_members`，组成员以外键引用设备（设备删除时级联）；确认存于 `alarm_acknowledgements` 表，以 `(device_id, opened_at)` 为主键。
